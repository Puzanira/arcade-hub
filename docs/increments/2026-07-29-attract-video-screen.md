   удаляются вместе с навигацией — зафиксировать в §прогресса).
5. Скриншоты: кадр видео в бездействии (чистый, без UI); зарядка Сизифа поверх

заполняет реф-экран целиком). Ошибка декода логируется, экран остаётся чёрным (не краш).

**Список/навигация удалены полностью.** `HubMenuController` теперь attract-хост: janitor-свип
(DDOL) + постройка видео-экрана; модель/строки/курсор/джойстик-листание/шрифты — выпилены.
`HubMenuModel.cs` и `HubMenuModelTests.cs` УДАЛЕНЫ (навигации больше нет — модель мертва);
навигационно-рендерный PlayMode-тест `Menu_RendersFounderLayout_NavigatesAndWraps` УДАЛЁН
вместе с механикой (фиксация по контракту п.4); капчер-тест 5×[PLAY] удалён (списка нет).
EditMode-цепочка «битый конфиг → не краш» переехала с меню на HoldToLaunchController
(единственный конфиг-потребитель на экране): пустой конфиг → 0 слотов, Tick не кидает.

**Никакого текста.** Из hold-to-launch удалён текст-хинт «Удержи / крути…» (ChargeHint) —
поверх видео только шкала и тематический дождь. Единственное исключение решения гейта 2 —
«СКОРО»-оверлей при полной зарядке soon-слота — ОСТАВЛЕН (показ основательнице на гейте).
Дополнительно для «чистого кадра» в бездействии: ШКАЛА (bg+fill) видима только при charge>0
(SetBarFill — единая точка), idle-кадр = только видео.

**Тесты (новый файл AttractVideoPlayModeTests).** (1) видео живо: isPlaying после ожидания,
loop=true, кадры реально идут (frame>0), Direct-аудио + аудиотрек в клипе, рект экрана кроет
реф-вьюпорт; (2) one-hot дождь: для слотов 0 (Crank/Boulder), 1 (Red/MilkBottle) и 5
(HeightA/десять цветов параллельного инкремента — сет НЕ тронут) зарядка до ~30% сыплет
ТОЛЬКО спрайты своего слота — ожидания читаются из shipped-конфига, не хардкодятся; после
отпускания куча очищается (передача эксклюзивности); (3) капчеры hub-video-idle.png (charge=0,
бар скрыт, дождя нет) и hub-video-charge.png (реальная зарядка крана ~50%, валуны поверх
видео). Прежние launch/exclusivity/hold-тесты живы без изменений; RedPress-регрессия
сохранена (убрана только ссылка на несуществующий курсор).

**Editor-тулзы.** Капчеры HubEditorTools/RainSpriteGenerator больше не строят меню-фон
(в edit-mode видео не декодируется) — тёмная заливка камеры; их flower/rain-позы целы.

**Каприз клока VideoPlayer + fallback (важно).** На macOS НЕфокусный редактор (тесты из
терминала, батч) готовит клип нормально, но AVPlayer-клок отказывается стартовать: `Play()`
оставляет плеер paused — без ошибки, кадры не идут (диагностировано вживую: `isPaused=true`
сразу после Play при `isPrepared=true`; `StepForward()` при этом декодирует). Решение в
`AttractVideoScreen`: сторожок — если Play не завёлся за ~2 с, переход на ручной пошаговый
прогон (`StepForward` по realtime-клоку, ручной луп через `frame=0`; БЕЗ звука в этом
режиме; лог-warning). Фокусный редактор/сборка стойки играют обычным Play СО ЗВУКОМ и в
fallback не заходят. Тест-ожидания видео — по wall-clock (не кадрам: анфокус гонит кадры
быстрее реального времени). Сим `IsShowingFrames` = клок ИЛИ fallback. Страховочный
`Assert.Ignore` для батча-без-декода оставлен, но ФАКТИЧЕСКИ батч зелёный полностью:
финальный CLI-прогон — EditMode 35/35, PlayMode 14/14, 0 skipped (fallback степпит и в
батче). Idle-капча сикается в середину ролика (вступление почти чёрное); «не пусто»
капчи меряется и яркостью против фона, и внутренней вариативностью кадра (тёмный
line-art кадр иначе ложно считался пустым).

**nativeInput/LauncherReturn/janitor** — не тронуты (janitor-вызов переехал в новый Start
attract-хоста тем же кодом).
