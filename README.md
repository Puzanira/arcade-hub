# Аркадный автомат AI Game Studio

Физический аркадный автомат: корпус, самодельная Arduino-электроника и семь
игровых слотов. Игрок ничего не выбирает в меню — он берётся за орган управления
и держит его ~5 секунд, полоска заряда доходит до конца, и запускается та игра,
которая к этому органу привязана. Выход обратно в меню — кнопка «меню», в любой
момент партии.

Восемь логических контролов: **крутилка**, **красная / зелёная / «!» / «меню»**
(кнопки), **датчик высоты A** и **датчик высоты B** (бесконтактные, под ладонь),
**джойстик**. Игры не читают железо напрямую — только фасад `ArcadeInput` из
пакета `arcade-controls`, за которым стоит сменный backend: последовательный
порт, когда плата воткнута, и клавиатура, когда нет. Как именно контролы разложены
по платам — дело сборки, система на это не завязана (см. «Контроллеры»).

Этот репозиторий (ветка `handout`) — **лаунчер**: Unity-проект с меню автомата.
Игры в него не вкопированы, они подтягиваются пакетами по git-ссылкам с
фиксированными пинами.

## Запуск

* Unity **6000.5.3f1** (ровно эта версия), git в PATH.
* `git clone -b handout https://github.com/Puzanira/arcade-hub.git`
* Открыть проектом **`arcade-hub/components/unity-game`** (не корень репозитория).
* Сцена **`Assets/_Project/Scenes/HubMenu.unity`** → Play.

Пакеты Unity вытянет сам при первом открытии.

## Контроллеры

### Принцип: сборка любая

Система не знает и не хочет знать, из скольких плат собран твой автомат.
Лаунчер сам сканирует все USB-порты; плата, которая прошла рукопожатие и шлёт
строки протокола, подхватывается на лету. Отсюда:

* **Контролы раскладываются по платам в любой комбинации** — все восемь на одной
  плате, или две платы, или три. Ограничение ровно одно: две платы не могут
  представиться одним и тем же именем.
* **Роль платы определяет не имя, а поток строк.** Имя — просто «привет»;
  какие контролы плата ведёт, решается по типам строк, которые она реально
  шлёт. Одна плата может слать все три типа сразу.
* **Горячее втыкание.** Воткнул — контролы перешли на плату; выдернул — сами
  вернулись на клавиатуру. Настроек в игре нет.
* **Чего нет на платах — остаётся на клавиатуре**, покомандно. Собрал только
  крутилку и кнопки — джойстик и датчики продолжат читаться со стрелок и
  `Q/A`, `E/D`.

### Протокол

115200 бод, строки ASCII, разделитель — перевод строки.

**Рукопожатие.** Хост пишет в порт `?`, плата отвечает строкой
`BOARD,<ИМЯ>`. Имя должно быть одним из трёх: `CABINET_PANEL`, `JOYSTICK`,
`GESTURE_SENSORS` — какое именно, роли не играет, это только идентификатор для
дедупликации портов. Плата, которая не ответила или ответила чем-то иным,
игнорируется. На `?` надо отвечать в любой момент, не только при старте.

**Строки данных** (плата шлёт их непрерывно, каждая — полный снимок):

| Строка | Поля | Что даёт |
|---|---|---|
| `C,<крутилка>,<red>,<green>,<bang>,<menu>` | крутилка `0..1023` (analogRead), кнопки `0/1` | крутилка + четыре кнопки |
| `J,<up>,<down>,<left>,<right>` | `0/1` | джойстик |
| `G,<left_mm>,<right_mm>` | миллиметры, `-1` = нет цели | датчики высоты A и B |
| `G,<left_mm>,<right_mm>,J,<up>,<down>,<left>,<right>` | то же, одной строкой | датчики + джойстик с одной платы |

Пересчёт: расстояние `100 мм` → контрол `1.0`, `600 мм` → `0.0` (ближе — больше),
за пределами полосы зажимается; крутилка — шум ниже `30` отбрасывается, дальше
`1.5 °/с` на единицу. Полоса и коэффициенты — тюнинг `SerialTuning`, не протокол.

Этого достаточно, чтобы собрать свою разводку под свою плату: важны только
формат строк и рукопожатие, а не то, какие пины куда идут.

### Референсные прошивки — как примеры

Готовые скетчи, с которых удобно начать. Это наша сборка, а не требование:

* `Firmware/CabinetPanel/CabinetPanel.ino` (репозиторий `arcade-controls`) —
  крутилка-энкодер и четыре кнопки, шлёт `C,…`, представляется `CABINET_PANEL`.
  Разводка и сборка расписаны в
  [`docs/LESSON_WIRING.md`](https://github.com/Puzanira/arcade-controls/blob/main/docs/LESSON_WIRING.md);
  её пины:
  ```
  D2 = красная   D3 = зелёная   D4 = «!»   D5 = меню (TTP223, HIGH = касание)
  D6 = энкодер CLK   D7 = энкодер DT   (+/VCC → 5V, GND → GND)
  ```
* `ArduinoFirmware/CombinedBoard/CombinedBoard.ino` (репозиторий `lady_bug`,
  ветка `arcade-contract-repack-v2`) — авторская плата: джойстик и два датчика
  расстояния на одном Arduino, шлёт объединённую строку `G,…,J,…`,
  представляется `JOYSTICK`. Рядом лежат раздельные варианты
  `Joystick/Joystick.ino` и `GestureSensors/GestureSensors.ino`.

> **Набор органов у тебя другой?** Напиши, какая плата и какие органы есть
> физически — соберём прошивку под тебя. Все восемь контролов умещаются и на
> одну плату.

### Заливка: какая у тебя плата

Референсные скетчи — обычные, без привязки к модели: подходят любому
классическому Arduino (Uno, Nano, Mega, Leonardo, Micro), пины `D2`–`D7` есть на
всех, менять в коде нечего.

1. Название платы обычно написано на текстолите («UNO», «NANO», «MEGA»); если
   стёрлось — воткни и посмотри, что появилось в **Tools → Port**.
2. Arduino IDE: **Tools → Board → …** (у Nano ещё **Tools → Processor →
   ATmega328P**), затем **Tools → Port** и **Upload**.

> **Экзотику — ESP32, ESP8266, RP2040 / Raspberry Pi Pico и подобное — вслепую
> не заливать.** Другая нумерация пинов и логика 3.3 В вместо 5 В: сигнала
> можно не получить, а вход — спалить. Сфотографируй плату и пришли фото, мы
> адаптируем прошивку.

> **Порт держит только один процесс.** Открытый Serial Monitor или второй Unity
> в Play отбирают плату. Держи запущенным что-то одно.

### Проверка контролов — первым делом на автомате

> Windows-слой чтения плат написан, но **на живом железе не проверялся** — у
> студии нет Windows-машины, всё покрыто тестами и прогнано на Mac. Поэтому
> первый шаг на автомате — прогнать все восемь контролов.

Готовой сцены-стенда в пакете нет, собирается за минуту:

1. Воткнуть все платы, какие есть в сборке.
2. Новая сцена → пустой GameObject → добавить компоненты
   **Arcade Controls / Arcade Input Runner** и
   **Arcade Controls / Demo Controls Panel** → Play.
3. Панель рисует восемь строк-индикаторов: крутилка, четыре кнопки, оба датчика
   высоты, джойстик. Пройти рукой по каждому собранному органу — соответствующая
   строка должна ожить. Контролы, которых в сборке нет, будут отзываться на
   клавиатуру — это нормально.

Если плата не видна или контрол не шевелится — открой **Window → General →
Console**, скопируй весь текст ошибок и предупреждений (особенно строки
`[SerialBackend]`) и пришли нам: по ним сразу видно, драйвер это, занятый порт
или наша ошибка.

### Windows

Автомат стоит на Windows-ПК, и здесь три отличия от Mac.

**Драйвер.** Платы с китайским чипом **CH340 / CH341** (почти все
дешёвые клоны) без драйвера в Windows не видны вообще — `COM…` просто не
появляется. Ставится один раз: вместе с Arduino IDE (свежие версии подтягивают
сами при первой заливке) либо вручную с сайта WCH —
`https://www.wch-ic.com/downloads/CH341SER_EXE.html`. После установки переткни
плату, при упорстве перезагрузи ПК. У оригинальных Uno / Mega (ATmega16U2) и
Leonardo / Micro драйвер встроен в Windows.

**Проверка, что система видит плату.** Диспетчер устройств (Win+X) → «Порты (COM
и LPT)»: каждая воткнутая плата — строка вида `USB-SERIAL CH340 (COM4)`. Номер
порта знать не нужно, игра перебирает все. Пусто или «Неизвестное устройство» с
жёлтым знаком — это драйвер.

**COM-порт эксклюзивен.** Главное отличие от Mac: порт может держать только одна
программа. Открытый Serial Monitor → игра эту плату **не увидит вообще** (на Mac
увидела бы, просто с рваными показаниями). Залил прошивку → закрыл Serial
Monitor (лучше всю Arduino IDE) → запускаешь игру.

### Клавиатурный фолбэк

Каждый контрол независимо: нет живой платы, которая его ведёт — читается с
клавиатуры. Так работает и разработка без железа (все семь игр проходятся с
клавиатуры целиком), и неполная сборка, где часть органов ещё не собрана.

| Контрол | Клавиша |
|---|---|
| Крутилка | колесо мыши |
| Красная кнопка | `Э` (`Quote`, слева от Enter; на латинице `'`) |
| Зелёная кнопка | `Enter` |
| Кнопка «!» | `1` |
| Кнопка «меню» | `Esc` |
| Джойстик | стрелки ← ↑ ↓ → |
| Датчик высоты A | `Q` вверх / `A` вниз |
| Датчик высоты B | `E` вверх / `D` вниз |

Датчики высоты эмулируются: значение растёт, пока держишь «вверх», падает на
«вниз» и само возвращается к нулю, если не держать ничего (убранная рука).
Раскладка лежит в
`Runtime/Resources/ArcadeControls/default-keyboard-mapping.json` пакета
`arcade-controls`; в скачанном виде пакет read-only (`Library/PackageCache/…`),
менять её — в репозитории `arcade-controls`.

## Если что-то не так

* **`Package [com.aigamestudio.…] cannot be found`** — репозитории публичные,
  дело не в доступе: проверь сеть и
  `git ls-remote https://github.com/Puzanira/arcade-hub.git` (должен напечатать
  хеши, ничего не спрашивая).
* **`No 'git' executable was found`** — git не в PATH; поставить и перезапустить
  Unity.
* **Unity не видит обновлённые пины** — снести `components/unity-game/Library` и
  `Temp`, открыть проект заново.
* **Окно Game пустое** — не открыта сцена `Assets/_Project/Scenes/HubMenu.unity`.
* **Игра не стартует из меню** — держать орган дольше, заряд ~5 секунд.
* **Нажатия не проходят** — кликнуть в окно Game, чтобы оно получило фокус.
* **Нет нужной версии Unity** — Unity Hub → Installs → Install Editor → Archive,
  либо ссылка `unityhub://6000.5.3f1`. Модули не нужны, играем из редактора.
